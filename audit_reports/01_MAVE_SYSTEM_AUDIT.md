## 1. Architectural Overview

MAVE is structured as an **Electron-based hybrid desktop AI operating environment and autonomous agent harness**. It combines:
1. **Desktop Shell & Presentation Layer**: Electron 38.0.0 (`src/main/main.js`, `src/renderer/home.js`, `src/renderer/index.html`) using HTML5, Tailwind-styled components, and IPC bridges (`src/preload/preload.js`).
2. **Local Inference Engine**: An embedded `llama-server.exe` (Vulkan build `b11276` in `C:\Users\ryzen\AppData\Roaming\mave\local-ai\bin\`) managing local GGUF models directly via HTTP API on port 8080/8081, supplemented by a secondary AirLLM layer-streaming Python server (`airllm_server.py`) and optional external Ollama bridge (`http://127.0.0.1:11434/v1`).
3. **Specialized Multimodal ONNX Engines**: Native in-process Node.js ONNX runtimes (`onnxruntime-node` v1.21.0) and C++ binaries for Text-to-Speech (Kokoro ONNX in `vendor/voice/`), Speech-to-Text (Whisper base.en in `vendor/speech/`), and Math OCR (Pix2Text MFR in `vendor/math/`).
4. **Computer Control & Automation Harness**: Low-level mouse, keyboard, and display capture via `@nut-tree/nut-js` and native Windows bindings (`src/main/computer.js`).
5. **Multi-User & Remote Mesh Bridge**: Embedded Express HTTP/WebSocket server (`src/main/remote/web.js`, port 3000), cloudflared tunnel daemon (`vendor/cloudflared/cloudflared.exe`), and role-based user management (`src/main/users.js`).
6. **Autonomous Goal Engine**: DAG-based multi-step autonomous planning engine (`src/main/autonomous/goal_graph.js`, `task_runner.js`) coordinating tool execution and fallback routines.

## 3. Key Architectural Findings for AI Hardware Architects

1. **Local Inference Decoupling**: MAVE does not embed the LLM weights inside the Electron renderer process. Local inference is executed out-of-process via `llama-server.exe` (using the Vulkan graphics compute API) or via AirLLM Python. This isolates GPU crashes from crashing the user interface.
2. **Single-User Physical Seat Constraint**: While MAVE possesses an enterprise-grade `UserManager` capable of handling multiple authenticated users over HTTP/WebSockets (`src/main/users.js`, `src/main/remote/web.js`), **OS automation (`src/main/computer.js`) operates directly on the active Windows session desktop**. If two users trigger desktop automation simultaneously, their mouse and keyboard events will conflict directly.
3. **Multi-Model Concurrency**: The default configuration runs the embedded `llama-server.exe` with a single loaded model slot. Switching between general text (`Qwen3-4B`) and vision (`Qwen3-VL-8B`) requires model reloading unless dual server instances are spawned on separate ports.
